NoRisk Addon Lib

Wiederverwendbare Java-Helfer für eigene NoRisk-Client-Add-ons: Module und HUDs registrieren, Werte anbinden und UI-Komponenten erstellen.

Library-JAR herunterladen → Quellprojekt herunterladen →
Für Add-on-Entwickler, nicht für Spieler: Das JAR ist eine Java-Library und kein Fabric-Mod. Binde/bündle die Library-Klassen in deinem Add-on. Spielende müssen keine separate Library-Mod installieren.

Was ist enthalten?

  • `NoRiskAddonLib.registerModule(...)` und `registerHud(...)` für die NRC-Registrierung.
  • `AddonModule` mit Helfern für Boolean-, Integer-, Dezimal- und Button-Values.
  • `AddonHud` als Startpunkt für ein eigenes verschiebbares HUD.
  • `NoRiskUi` für Labels, Abschnitte, Buttons, Toggles und numerische Slider in `FlowLayout`s.
  • Das Quellprojekt-ZIP enthält Java-Quellcode, Gradle-Projekt und Wrapper, aber keine privaten NRC-Dependency-JARs.

Voraussetzungen und Build

Das veröffentlichte Projekt ist auf Java 25, Minecraft 26.3 und Fabric Loader 0.20.1 ausgelegt. Für den lokalen Build werden zusätzlich die passenden `norisk-client.jar`, `nrc-owolib.jar`, `nrc-abstraction.jar` und `kotlin-stdlib.jar` gebraucht. Diese NRC-JARs sind aus Lizenz- und Versionsgründen nicht in den Downloads enthalten.

  1. Lade das Quellprojekt-ZIP herunter und entpacke es.
  2. Lege die für deine Zielversion erlaubten NRC-/owo-lib-JARs in einen lokalen Ordner, beispielsweise `D:\nrc-libs`.
  3. Baue unter Windows mit Java 25: .\gradlew.bat build -PnrcLibsDir="D:\nrc-libs".
  4. Das fertige Artefakt findest du unter build\libs\norisk-addon-lib-1.0.0.jar.

Im Add-on einbinden

Lege die heruntergeladene Library in den `libs`-Ordner deines Add-ons und ergänze die Gradle-Abhängigkeit. Da Gradle normale `implementation`-Dateien nicht automatisch in das Mod-JAR bündelt, verwende deinen vorhandenen Bundling-/Shadow-Schritt und verlagere das Library-Package in ein Add-on-eigenes internes Package. Bette weder Minecraft/Fabric noch die NRC-Laufzeit-JARs ein.

dependencies {
    addonLib files('libs/norisk-addon-lib-1.0.0.jar')
}

shadowJar {
    configurations = [project.configurations.addonLib]
    relocate 'gg.norisk.addonlib',
             'gg.norisk.addons.meinaddon.internal.addonlib'
}

Schnellstart: Modul, Values und UI

public final class ExampleModule extends AddonModule {
    private final BooleanValue enabled;
    private final NumericValue strength;

    public ExampleModule() {
        super("Beispiel", ModuleCategory.QUALITY_OF_LIFE,
              true, false, true);

        enabled = booleanValue("enabled", true,
                "Aktiv", "Schaltet das Feature");
        strength = decimalValue("strength", 1.0f,
                0.1f, 5.0f, 0.1f,
                "Stärke", "Legt die Stärke fest");
    }

    @Override
    public Function1<FlowLayout, Unit> buildCustomUi() {
        return customUi(panel -> {
            NoRiskUi.section(panel, "Mein Add-on");
            NoRiskUi.actionButton(panel, "Aktion", this::runAction);
            NoRiskUi.toggle(panel, "Aktiv",
                    enabled::get, enabled::set);
            NoRiskUi.slider(panel, "Stärke", 0.1, 5.0, 0.1,
                    () -> strength.get().doubleValue(),
                    value -> strength.set((float) value));
        });
    }

    private void runAction() {
        // Eigene Add-on-Aktion
    }
}

Registrierung und eigenes HUD

// Im Client-Entrypoint:
NoRiskAddonLib.registerModule(new ExampleModule());
NoRiskAddonLib.registerHud(new ExampleHud());

public final class ExampleHud extends AddonHud {
    public ExampleHud() {
        super("Beispiel HUD", true, true, true,
                () -> UIComponents.label("Hallo aus dem HUD"));
    }
}

Vorhandene NRC-UI ändern

Die UI-Helfer bauen Komponenten für `FlowLayout`s und eignen sich für Erweiterungspunkte wie `buildCustomUi()`, `buildNavbarActions(...)`, `buildCategoryUi(...)` oder eigene HUDs. Um ein beliebiges bestehendes NRC-Element zu ergänzen oder dessen interne UI-Struktur zu ändern, brauchst du weiterhin einen passenden versionsabhängigen Hook/Mixin. Die Library kann keinen stabilen, allgemeinen Hook für fremde Screens bereitstellen.

Versionshinweis: Die Modul-, HUD- und Value-Klassen sind interne NoRisk-APIs. Prüfe die Zielversion und teste dein Add-on im konkreten Client-Profil. Der API-Vertrag kann sich ohne Vorwarnung ändern.
