Eigenes Modul erstellen

Ein Modul ist die Funktion, die Nutzende im Menü ein- und ausschalten können. Beginne mit einer kleinen Client-Funktion und hänge erst danach NRC-spezifische Menüs an.

API-Hinweis: Die NRC-Klasse gg.norisk.ui.api.module.Module und der ModuleProvider kommen aus bestehenden Community-Beispielen. Signaturen können sich ändern. Prüfe sie im Build, für den du entwickeln willst; dies ist kein offizieller API-Vertrag.

Schritt für Schritt

  1. Fabric-Template anlegen. Minecraft-Version und Fabric Loader auswählen, Gradle-Projekt in IntelliJ importieren und das unveränderte Template einmal bauen.
  2. Mod-ID setzen. In fabric.mod.json eindeutige Mod-ID, Namen, Version und clientseitigen Entry-Point eintragen.
  3. Funktion isolieren. Eigene Klasse schreiben, die ihre Listener beim Einschalten registriert und beim Ausschalten wieder entfernt.
  4. NRC-Verfügbarkeit prüfen. NRC-Klassen nicht in statischen Feldern des frühen Entry-Points referenzieren, wenn das Addon auch außerhalb von NRC starten soll.
  5. Registrierung ergänzen. Erst wenn NRC bereit ist und die Zielversions-API bestätigt ist, Modul instanziieren und in den Modul-Provider eintragen.
  6. Menü und Lifecycle testen. Ein-/Ausschalten, Weltwechsel, Disconnect und erneutes Aktivieren prüfen.

Lifecycle-Grundidee

public final class BeispielModul {
  private boolean aktiv;

  public void aktivieren() {
    if (aktiv) return;
    aktiv = true;
    // Client-Event-Listener einmal anmelden
  }

  public void deaktivieren() {
    if (!aktiv) return;
    aktiv = false;
    // Listener wieder entfernen und Tasks stoppen
  }
}

Das Beispiel zeigt die Struktur, nicht die Signatur eines konkreten NRC-Moduls. Sorge dafür, dass mehrfaches Aktivieren keine doppelten Listener erzeugt und beim Ausschalten nichts weiterläuft.

Was gehört in ein gutes Modul?

  • stabile interne ID und verständlicher Anzeigename
  • klare Kategorie, Beschreibung und Standardzustand
  • eigene gespeicherte Einstellungen mit sinnvollen Defaults
  • Null-Checks für Welt/Spieler und saubere Aufräumlogik
  • keine Aktionen, die Serverregeln oder Schutzmechanismen umgehen
